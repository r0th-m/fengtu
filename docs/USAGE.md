# USAGE.md —— 丰图用户操作手册

> 对照 0.26.0-m4-multiuser 实现写。每个功能给「什么时候用 / 怎么用 /
> 注意事项」。AI 相关口径集中在文末 §9，先记住三句话：**机器产出全是候选，
> 不是结论；判断权归人；每条判断必须能锚到「主机 + 源 + 行号 + SHA256」。**

## 1. 登录与首启

- 首次部署后打开平台地址（默认 `http://<主机>:8200`），引导页创建首个
  管理员：口令 ≥8 位且含字母+数字。此入口只能用一次。
- 之后日常登录用账号口令。会话 12 小时绝对过期；连续 5 次登录失败锁定
  15 分钟（锁定期间正确口令也拒）。
- 改密：左下角用户卡 → 修改密码（验旧口令）。
- 角色两档：**admin** 全权（含用户管理、AI 配置写、全局知识库写）；
  **operator** 案件操作全能做，只是不能碰用户管理和全局配置。案件对
  所有登录用户可见（团队共享口径，无行级隔离）。

## 2. 建任务：新建应急任务向导

**什么时候用**：每一次应急 = 一个案件。入口：侧边栏「新建应急任务」
（/cases/new）。

各字段说明：

1. **任务名称**：留空则取首个采集包文件名（去扩展名）。**注意**：挂了包
   之后名字锁定——上传归并按名字认案件，改名会把后续的包挂到别的案件
   （页面有如实提示）。
2. **应急类型**：固定枚举单选——勒索响应 / WebShell 排查 / 入侵排查 /
   数据泄露 / 其他。影响目的预设和知识库的预勾选，随时可在向导里改选，
   预勾选会按类型重套。
3. **应急背景**：自由文本（≤4000 字），可从模板下拉回填四段骨架
   （发现经过/影响面/已知 IOC/时间窗）再改。写给人和 AI 看的上下文。
4. **采集包上传**：选中即传、可多次追加（一案多包：一次应急收 N 台主机
   N 个包）。每包一张状态卡，「校验 → 上传 → 摄入」三段进度全程可见。
   上传中的包没传完不能提交建案；失败的卡可重试或移除。已摄入的包不能
   从向导里回收（如实）。
5. **应急目的预设**：复选（确认入侵入口/确定影响范围/找驻留点/数据泄露
   面/攻击时间线，按类型预勾选推荐）+ 自由补充。这些目的会播种为意图图
   的 goal 节点——**只播种不消耗 AI**，AI 排查在案件页按需发起。
6. **知识库条目**：勾选本案生效的排查启发式（内置条目 + 用户条目，
   按类型预勾选）。不勾 = 本案 AI 排查不注入这些参考（存量老案件默认
   零勾选，案件页「知识库」tab 可补）。

提交即跳案件页。注意：**建案不会自动起 AI 分析**——防创建即烧钱，
排查节奏由人掌握。

## 3. 案件页：十一个 tab 怎么用

案件页（/cases/:id）默认停在「探索链路」。顶部任务头常驻：任务名（铅笔
行内改名）、类型徽标、状态机外显（探索中·N 执行中 / 待审批 N / 待执行
N / 静默——如实推导，不装忙碌）、源/候选/待裁决计数、SSE 实况点、
审批铃铛。

### 3.1 探索链路（意图图）——主视图

**什么时候用**：看 AI 排查进行到哪、往哪长，随时介入。

**怎么读**：
- 圆角卡片节点，从左到右按层级流式布局。五型五色：goal 目标（青）/
  intent 意图（蓝）/ fact 事实（灰绿）/ finding 候选（琥珀）/ hint
  线索（灰）。
- 状态 chip：open 灰（待执行）/ running 蓝脉冲 / supported 绿 /
  denied 灰 / doubt 琥珀 / closed_exhausted 斜纹（时间耗尽，非失败）/
  awaiting_approval 红脉冲+红角标（等你批）/ parked 灰虚线框（停车场）。
- 连线标血缘：派生 / 源自 / 产出 / 证明（虚线）。
- 交互：点卡 → 右侧详情（文本/血缘导航/执行过程流逐步/证据锚点跳内容
  树）；双击折叠子树；滚轮缩放、背景平移；左下缩放控制、右下小地图；
  「主机泳道」开关按主机聚簇（多机案件用）。

**怎么介入**：
- 头部手写入口双模：**意图** = 直接进图排队执行（烧 AI）；**线索** =
  挂图不执行，下轮 worker 能看到（零消耗）。
- 节点详情：running 的可**纠偏**（发一段话打断当前轮、同会话续跑，
  优先级高于当前探索方向）或**停止**；open 的可**终止**（未派发即关闭，
  不消耗 AI）；待批的**批准/拒绝**。
- **注意**：纠偏/停止只对在跑意图；终态节点没有操控钮（不装可操控）。
  意图图是 SVG 渲染，数百节点以上的特大案流畅度未实测。

### 3.2 播报板（右栏上部，交流区上方）

**什么时候用**：图回答「结构」，播报板回答「什么时候该我介入」。

- 四档流水：意图诞生 / 中间发现 / 意图终结（带置信色 chip）/ 审批事件。
- 诞生档行内就有「停止」「纠偏」按钮；待批的带「去审批」跳转。
- 中间发现可展开全文、点证据锚点跳内容树。
- 可折叠（记忆折叠态）；自动吸底不抢滚动。
- **注意**：播报是实时流水不是历史账——只存进程内缓冲，服务重启即空；
  历史过程流去看节点详情，不缺。

### 3.3 候选发现（待审区）

**什么时候用**：裁决规则/算子扫出的机器候选——这是「判断权归人」的
主阵地。

- 每张卡：证据等级 badge（强疑似/疑似/弱信号，系统按证据结构算，不是
  模型自评）+ 一句话 + 命中规则/算子 + 原文 snippet + 证据锚点 chip
  （源:行号，点击跳内容树对应行高亮）+ 原始统计量（z-score/cv/频次等
  直给，不包装假精度）。
- 每张卡焊死「命中≠结论：机器候选，判断权归人」。**接受 / 排除**两个
  醒目按钮，裁决留审计锚真人。
- **注意**：裁决是一次性的——并发下两人裁同一候选只成一个，另一个
  收到 409「该候选已被他人裁决」。裁决过的候选是历史判断，改判解析
  不会联动清理。
- 全局视角：侧边栏「发现」页跨案件汇总（每案最新 200 条，超限如实标；
  裁决仍回案件页做）。

### 3.4 审批

**什么时候用**：AI/规则派生的**批量执行意图**（scope=all，如「邻机
波及」）创建即挂起，等你点头才派发。人提的意图不过闸。

- 案件页「审批」tab：待批队列阻塞式呈现（焊死「执行阻塞中——批准前
  该意图不会被派发」+ 已等待时长 + 来源 + 批量标），一键批准/拒绝；
  下方审批历史（审计链投影）。
- 侧边栏「审批记录」（/system/approvals）是跨案件统一收件箱，徽标计数
  含停车场待处置（title 有构成说明）。
- **注意**：批准/拒绝/停止全进审计哈希链；并发裁决冲突 409 如实显错。

### 3.5 停车场

**什么时候用**：意图链有预算三闸（每意图派生扇出 5 / 每章 30 / 每案
200，系统配置页可调）。AI 派生超闸的线索不丢，停进停车场；AI 调查中
主动登记的章外线索也停这里。**展开永远人点**。

- 「待处置」区：每条带来源意图/归属建议/AI 评估建议（deploy/dismiss，
  只是建议）；「展开」= 转 open 进图执行，「丢弃」= 关闭留痕。
- 顶部预算消耗条：案件 x/200 + 各章分布。
- **注意**：展开后它的子派生仍受三闸约束（预算是持续约束，不是一次
  通行证）；出入全进审计。手工写的意图/线索不受三闸限制。

### 3.6 内容树

**什么时候用**：看采集包原文、回查证据锚点、纠正格式判定。

- 左树按「主机 → 包 → 源」聚簇（散件主机为空如实排前），叶子带行数/
  状态（已解析/已登记/待确认/存疑/解析失败/未摄入）/类别/判定；右侧
  原文查看器（行号定位/跳行/翻页）。
- **待确认**条目（指纹置信度 <0.9 的文本源）：行内「改判」或查看器头部
  「改判为 raw-text 原文并解析」——改判即按新格式重解析（先删旧事件
  再重插，不留双份）。措辞用「改判」：这是人对格式的判定，不是候选结论。
- **注意**：evtx/hive 等非文本源不能按行回查（查看器走事件视图，锚点
  按位次估窗，落窗外如实标）；GBK 源按 UTF-8 呈现（不可解码字节如实
  替换）；解析后坏行率 >5% 的源会挂「存疑」标——结果可用但要打折看。

### 3.7 检索

**什么时候用**：全文/字段直查事件库。

- 全文词（raw 大小写不敏感子串）+ 字段条件构造器（eq/contains，多条件
  AND，字段可自由输入）+ 时间窗（全期/近1h/近24h/自定义）+ 源多选。
- 结果栏如实显示「N 条命中 · 耗时 X ms」；行展开看归一字段；锚点跳
  内容树。
- **注意**：结果按主键序（源+行号）返回，不按时间排序（3000 万行排序
  与亚秒不可兼得）；无时区的源不参与时间窗过滤（如实，不是 bug）；字段
  缺失的源天然不命中字段条件。

### 3.8 时间线

**什么时候用**：看全案事件的时间密度分布，找异常窗口/断档。

- 小时桶密度条，点条查桶内事件（走检索层）；无时区源单列展示（路径+
  事件数，不静默）。
- **注意**：桶粒度固定小时；跨季案件超 4100 桶截断如实标。

### 3.9 约束

**什么时候用**：立人工红线，约束 AI 排查行为——如「不得触碰 x.x.x.x
段」「只查 7 月 25 日之后」。

- 新增/删除（删除有二次确认），≤20 条/案。注入 worker 的最高优先段：
  「操作约束，冲突方向宁可不查」；约束清单查询失败时意图直接不执行
  （fail-closed，零 AI 调用，不裸奔）。
- **注意**：机器不会自动从背景里抽约束（那是猜，不做）——红线只能
  人显式立。

### 3.10 知识库

**什么时候用**：管理本案生效的排查启发式（建案时勾选的在这里改）。

- 勾选管理：生效徽标、全局被禁用的条目如实标「勾选不生效」；存量零
  勾选案件有 amber 提示。
- 保存回执如实带：差集条数 + 「对之后派发的 worker 生效，在跑的不追回」。
- 全局条目的新建/启停在「系统 → 知识库」（admin 写）；内置条目只能
  启停不能改（要改就另建用户条目）。

### 3.11 工作区

**什么时候用**：给案件补材料——客户提供的情况说明、外部情报、中间
笔记。AI 可读：在交流区说「读我工作区里的 xx 文件」，worker 会用
workspace_list/workspace_read 只读工具看本案工作区。

- 文件管理器全功能：新建目录/上传/下载/在线编辑文本（≤8MB）/删除
  （递归，二次确认）。与证据金库物理隔离——工作区里没有任何能碰到
  案件原件的通路。
- **注意**：工作区材料是用户提供的参考**不是证据**，AI 引用它时锚点
  仍只能锚采集物；写操作进审计，读/下载不落账。另有全局「工作空间」
  页（/function/workspace）两层导航进各案工作区；「未分配」区是旧版
  遗留，要归案请下载后到案件工作区重新上传。

### 3.12 报告

**什么时候用**：结案出报告。

- 六区段：概述（案件元数据）/ 应急目的达成（goal 状态，机器评估口径，
  收官定论归人）/ 已确认发现（人工 accepted 的候选，严重度降序，每条
  锚点四件=主机+源+行号+SHA256）/ 排查结论（supported fact）/ 三态
  裁决概况 / 证据覆盖（查过多少、缺口多少，如实）/ 处置建议（模板清单，
  标「需人核」）。
- 每条发现的血缘子图（起点→结论），点卡跳主图；markdown 一键下载。
- **注意**：报告是纯模板生成不走 LLM；覆盖缺口如实列，不硬编圆满。

### 交流区（右栏常驻 ChatDock）

**什么时候用**：和 AI 直接对话排查——「看看这台机的 3306 有没有被外部
直连」「读我工作区的 xx 文件」。

- 流式回答，工具调用过程帧可见（它查了什么、返回什么全程透明）。
- AI 答案里的锚点（源+行号）渲染成 chip 可点跳内容树；找不到行号不
  造锚（防臆造）。
- 输入框上方焊死「AI 产出均为疑似候选，判断权归人」。
- 会话持久化可续聊；「中断」按钮立即停当前回答（账标 aborted，不可续）。
- **注意**：AI 外发闸默认关，admin 在「系统配置 → AI 厂商设置」开闸
  配 key 后才能用；会话有 token 预算（默认 20 万），超了如实熔断。

## 4. 案件生命周期（任务列表页）

侧边栏「任务」（/function/tasks）：

- **改名**：行操作铅笔，或案件页头部行内改（Enter 保存 Esc 取消）。
- **归档**：案件从默认列表隐藏（「已归档」筛选看回）；归档案只读——
  意图引擎停派、分析/手写意图 409，在跑的意图跑完不掐。解归档即恢复。
- **删除**：双确认（对话框逐字输案件名 + 后端复核）。级联清 PG 各表 +
  CH 事件 + 工作区目录；**同哈希仍被他案引用的金库原件如实保留**（证据
  链不断）。有在跑任务/意图时拒绝删除（409 列出原因，先停再删）。
  **注意**：被删案件的审计条目原样保留（哈希链一条不动）；CH 事件删除
  是全表 mutation，大案要等几分钟（对话框 busy 如实等待）。

## 5. 封存导出 / 导入（跨实例迁移、案件移交）

- **导出**：案件页头「导出封存包」→ 单 zip（manifest + 案件/源/意图图/
  锚点 + vault 原件 + 全包 SHA256SUMS）。
- **导入**：任务列表「导入封存包」→ 逐文件哈希对账（失配 422 拒收）→
  **永远建新案**（名撞加「(导入)」后缀，不并案不覆盖）→ 从原件重跑
  解析派生事件 → 意图图按新 id 重映射。
- **注意（如实）**：待审候选和裁决**不随包**——导入后需重扫描、重裁决；
  执行过程流/停车场条目不随包；审计段只作快照随包走、不回插全局链；
  导入在跑的意图一律标记停止，迁移不续跑。

## 6. 多用户与用户管理（admin）

- 「系统 → 用户」：列表/新建（默认 operator 最小权限）/禁用/重置密码
  （重置即焚会话）/改角色/删除。保护闸：不能禁用/删除/降级自己；最后
  一个活跃 admin 受保护。
- operator 看不到「用户」导航，直访也进不去；后端 403 才是权限边界。
- 一切用户变更落全局审计（口令永不出账）。

## 7. 平台页速览

- **仪表盘**（/dashboard）：案件/数据源/候选/待裁决/待审批五卡 + 近 7
  天活动 + 案件状态分布（归档默认不含，单列如实标）。
- **LLM 录制**（/function/llm-records）：逐次厂商调用账（档位 off/
  metadata/full 在系统配置切；full 档可左右看 Request/Response）。
- **日志**（/system/logs）：进程内运行日志环形账（2000 行，重启清零
  如实标；过滤/暂停/加载更早）。
- **系统配置**（/system/settings，写操作 admin 专属）：AI 厂商（key
  密文不回显/外发开关/预算/代理与搜索自测按钮）、Agent 并发上限、
  意图链预算三闸、LLM 录制档位、版本信息。配置改动对**之后**的派发
  即时生效，在跑的不追回。

## 8. 一次完整应急的推荐动作序列

1. 新建应急任务：选类型、填背景（模板回填再改）、勾目的、勾 KB、传包
   （摄入随上传自动完成）。
2. 发起分析（如实：**当前前端没有「一键分析」按钮**——它随切片十的
   HeroUpload 退役了，入口待补）。两条路：
   - API 触发一键分析（解析 → 全量规则/算子扫描 → playbook 模板播种
     意图链）：
     `POST /api/cases/{id}/analyze`（body 可带 `playbook`、`deadline_at`；
     `seed_intents` 默认 true）；
   - 或案件页探索链路头部直接手写一条意图进图执行。
3. 探索链路看着图长；播报板盯介入时机；该批的批、该纠偏的纠偏。
4. 候选发现逐卡裁决（接受/排除）；检索/时间线/内容树补人工核查。
5. 需要补材料 → 工作区上传，让 AI 读；需要立红线 → 约束 tab。
6. 停车场定期清理（展开有价值的，丢弃噪声）。
7. 报告 tab 出 markdown，人审改写后交付；案件归档或封存导出移交。

## 9. AI 口径（每条都焊在产品里）

- **机器候选 ≠ 结论**：规则命中、算子发现、AI 答复全是候选；接受/排除/
  收官永远人点。全站禁「确认」类措辞。
- **判断权归人**：AI 派生的批量意图过人审批才执行；AI 对停车场条目只
  建议不展开；报告里 goal 达成是机器评估口径，定论归人。
- **锚点四件**：每条判断必须能锚到「主机 + 源 + 行号 + SHA256」；AI
  给不出锚点的结论系统自动降级「存疑（doubt）」。
- **只读工具集**：AI 只有六个只读工具 + 两个工作区只读工具；它碰不到
  写操作，删改数据从来不由它。
- **外发闸**：默认关，开了才有字节出机；token 预算耗尽如实熔断；
  每次工具调用进审计哈希链，逐次厂商调用可开录制回放。
- **网页搜索是参考不是证据**：联网搜索结果不能当锚点，结论锚点仍只能
  锚案件采集物。
